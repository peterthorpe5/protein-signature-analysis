1. PURPOSE OF THIS HANDOVER
---------------------------

This document is the complete technical and operational handover for the
standalone protein-signature-analysis repository. It records the scientific
question, the implemented code, the input and output contracts, the automated
label proposal system, the E3 defaults, the structural workflow, the
statistics, the explainable machine-learning layer, the cluster commands, the
quality checks completed in the development workspace and the remaining
scientific review responsibilities.

The package is deliberately named for protein signatures rather than E3
ligases. E3 ligases are the first production use case and therefore the
built-in default profile and ruleset, but the engine accepts a custom protein
hierarchy and custom evidence rules. A kinase, receptor, enzyme, transporter or
other protein-type project can use the same package without adding E3-specific
logic to the generic analysis engine.

This handover supersedes the earlier proposal to create an E3-only package
inside E3_project_draft. The resulting implementation is a separate reusable
repository. It can consume the completed E3 workflow as one adapter path, or
start from generic FASTA, labels, domains, structures and optional completed
OrthoFinder results.


2. DIRECT DEVELOPMENT OUTCOME
-----------------------------

The requested automated production-label proposal layer has been implemented.
It is additional to, and does not replace, the original reviewed-label path or
the synthetic smoke-test path.

The repository now has three clearly separated label routes:

  A. Human-reviewed route
     A named curator edits a complete assignment table and issues a
     checksum-bound approval. This is the only route whose marker sets
     scientific_interpretation_allowed to TRUE.

  B. Evidence-led provisional route
     The software combines versioned target rules with direct seed labels,
     annotation text, Pfam/domain evidence, optional OrthoFinder membership,
     structure eligibility and optional redundancy clusters. It proposes
     targets, abstains on weak or conflicting cases, builds outcome-blind
     matched controls, excludes label-defining features from confirmatory
     analysis, and publishes a complete audit bundle. It can run unattended
     only after the operator supplies --accept-provisional-evidence-labels.
     The outputs remain provisional hypothesis-generation results and are not
     represented as human reviewed.

  C. Synthetic smoke-test route
     The software creates deliberately artificial balanced target/control
     cohorts to test code execution. Its markers and filenames contain
     AUTOMATED_TEST_ONLY. Its results must never be interpreted biologically.

The distinction matters. An unattended full run is technically possible, but
automation cannot turn database annotations into experimental proof. The
implemented metadata prevents that accidental overstatement.


3. SCIENTIFIC QUESTION AND CLAIM BOUNDARY
-----------------------------------------

For each configured protein type or subtype, the package asks:

  * Which amino-acid k-mers are enriched in the target relative to an
    independently chosen background?
  * Which Pfam or other domain features are enriched after label-defining
    domains are removed from confirmatory testing?
  * Which imported or Foldseek-derived structural groups occur more often in
    the target?
  * Which discoveries retain the same direction in a frozen held-out
    validation partition?
  * Can a regularised classifier distinguish the target from the matched
    background without splitting homologous/redundant units across folds?
  * Which features contribute to that fitted model globally and for individual
    proteins, as described by SHAP values?

The package reports association and prediction. It does not prove biochemical
activity, catalytic mechanism, substrate binding, ligandability, causality or
fitness in a PROTAC system. A structural cluster associated with F-box
receptors, for example, is a testable family-level observation. It is not proof
that every member binds SKP1, recruits a substrate or has an accessible ligand
pocket.

The package must not pool all E3-related proteins into a single biological
class. RING, U-box, HECT, RBR, RING-Cys-relay, CRL scaffolds, CRL adaptors,
substrate receptors, SUMO E3s, NEDD8 components and UFM1 complex components
have different mechanisms and component roles. The built-in E3 profile keeps
these distinctions explicit.

8. GENERIC INPUT CONTRACT
-------------------------

8.1 Required FASTA

The FASTA is the protein identifier and sequence authority. Each identifier
must be unique and stable. Conflicting duplicate sequences fail validation.
The package does not silently rewrite identifiers.

8.2 Classification profile

The profile YAML defines:

  * the root, parent, target and control labels;
  * display names and aliases;
  * mechanistic classes and component roles;
  * assignment exclusivity groups;
  * labels eligible for positive assignment;
  * default target/background comparisons; and
  * whether structure evidence is required.

configs/profile.example.yaml is a small kinase example. The built-in name e3
loads the complete E3 profile.

8.3 Evidence rules

The evidence-rules YAML is separate from the profile and is validated against
configs/evidence_rules.schema.json. configs/evidence_rules.example.yaml is
paired with the kinase example profile.

Each label rule declares:

  rule_id
  label_id
  priority
  annotation_patterns
  specific_annotation_patterns
  exclusion_patterns
  required_domain_patterns
  supporting_domain_patterns
  allow_specific_annotation_only
  propagate_by_orthology

Global settings declare evidence scores, acceptance thresholds, the minimum
number of independent evidence groups, the winning-score margin, structure
requirements, HOG propagation policy and control-matching policy.

Rules are scientific authorities. Change ruleset_version whenever a pattern,
score, threshold, structure requirement or matching policy changes. Never tune
rules silently after looking at the desired result.

8.4 Generic protein metadata

protein_metadata.tsv must contain:

  protein_id
  species
  input_candidate

It must cover every FASTA protein. input_candidate accepts only TRUE or FALSE.
Several species values may use a pipe delimiter. Species is a control-matching
covariate. input_candidate can prevent upstream candidates from entering the
negative pool.

8.5 External annotations

external_annotations.tsv must contain:

  protein_id
  label_id
  annotation_text
  evidence_status
  evidence_source
  evidence_reference
  annotation_scope

label_id and annotation_text are individually optional, but the row must carry
meaningful evidence. An exact label is trusted direct evidence only when its
status is CURATED, EXPERIMENTAL, MANUALLY_REVIEWED or REVIEWED and its scope is
DIRECT or EXACT_PROTEIN. Repeated records from one named source remain one
evidence group.

8.6 Seed assignments

seed_assignments.tsv uses the standard complete label-assignment schema. Only
REVIEWED_POSITIVE rows are direct anchors. A proposed seed is not upgraded by
being placed in this file.

8.7 E3 seed catalogue

The existing e3_seed_catalogue.tsv can be supplied to the E3 route. Exact
per-seed information and cluster-associated information remain separate.
Cluster-associated annotation is weak context and cannot on its own turn every
cluster member into an E3 subtype. The catalogue's annotation_scope and
catalogue_source are retained.

8.8 Domain assessments

domains.tsv distinguishes:

  ASSESSED_WITH_HIT
  ASSESSED_NO_HIT
  NOT_ASSESSED
  FAILED

A missing row is not assumed to mean no domain. Required domains corroborate a
label but do not alone establish protein function.

8.9 Structures

structures.tsv records structure identifiers, coordinate paths, model source,
model version, sequence agreement, confidence and analysis eligibility. The
labeller uses structure only as an eligibility and matching covariate. It does
not use the discovered Foldseek cluster or structural motif to define the
target label that the same workflow later tests.

8.10 OrthoFinder

Supply one of:

  * a published orthofinder-results resource; or
  * a completed raw OrthoFinder 2.5.5 or 3 results directory.

HOG mode normally uses hierarchy node N0. LEGACY_ORTHOGROUP mode must not have
a hierarchy node. This package reads OrthoFinder outputs and never runs
OrthoFinder.

8.11 Optional redundancy clusters

Near-redundancy membership can be supplied explicitly. These memberships are
combined transitively with exact-sequence and OrthoFinder links. All members of
one resulting block remain together for cohort and validation operations.


9. AUTOMATED EVIDENCE-LABEL ALGORITHM
-------------------------------------

9.1 Input freezing

The software resolves every input path, validates it, records its byte size and
SHA-256 digest, and refuses to publish into an existing output directory. A
staging directory is renamed into place only after every table and marker has
been written.

9.2 Protein evidence contexts

For every FASTA protein, the labeller constructs one context containing:

  * sequence length and exact-sequence identity;
  * species and upstream-candidate state;
  * explicit domain assessment and domain identifiers;
  * structure availability, eligibility and mean confidence;
  * direct label evidence;
  * annotation text grouped by authority;
  * OrthoFinder membership; and
  * an independence-block identifier.

Authorities that disagree on species or candidate state fail closed rather
than being silently reconciled.

9.3 Evidence scoring

Each configured target rule is scored independently. Built-in E3 defaults are:

  ordinary annotation match                  2.0
  highly specific annotation match           4.0
  required Pfam/domain support                2.0
  supporting domain                           0.5
  compatible unanimous HOG propagation        2.0
  trusted exact positive label                5.0
  normal acceptance threshold                 3.5
  minimum independent evidence groups         2
  minimum winning-score margin                1.0

The values live in e3.yaml, not hidden Python constants. A domain alone cannot
reach the threshold. Ordinary annotation plus its required domain normally can.
The built-in E3 rules do not currently permit a specific annotation to stand
alone.

9.4 Evidence-group independence

Scores are accumulated by named evidence group, not record count. Ten rows
from the same annotation database cannot appear to be ten independent
confirmations. The strongest contribution within the group is retained.

9.5 Required domains and exclusions

An accepted rule must satisfy its required-domain expressions. Exclusion
patterns veto misleading text, such as terms that resemble a target class but
describe a different architecture. Every matched item and veto remains in the
audit table.

9.6 Hierarchical resolution

When a descendant and its ancestor both pass, the more specific descendant is
selected. Non-ancestral alternatives are accepted only if there is no trusted
direct conflict and the winner clears the configured score margin. Otherwise
the protein becomes AMBIGUOUS.

9.7 Abstention

The route uses four decision states:

  ACCEPTED
    Required evidence, score, groups, hierarchy and structure policy passed.

  PROPOSED
    Some target-like evidence exists but is incomplete or below policy.

  AMBIGUOUS
    Incompatible alternatives cannot be resolved safely.

  UNMAPPED
    No configured target evidence was found.

Only ACCEPTED targets and their selected controls receive
EVIDENCE_SUPPORTED_POSITIVE. Proposed, ambiguous and unmapped records do not
become training positives or controls.

9.8 Conservative HOG propagation

HOG propagation is optional and one generation deep. The recipient must:

  * share the selected HOG with at least the configured number of accepted
    anchors;
  * have anchors that resolve unanimously to one compatible rule label or
    ancestor;
  * use a rule that explicitly enables propagation;
  * contain the required domain architecture; and
  * pass the structure policy.

Propagated calls do not become recursive anchors during the same run. This
prevents a weak chain of inferred records from expanding indefinitely.


10. BACKGROUND-SELECTION DESIGN
-------------------------------

10.1 Why there is no universal housekeeping background

One housekeeping family is not a neutral protein background. It carries its
own conserved fold, length distribution, domain architecture, cellular role,
taxonomic distribution and annotation completeness. Comparing every E3 class
with one housekeeping family would make the housekeeping family's biology look
like an E3 depletion and would make unrelated E3 properties appear enriched.

The package therefore builds a clean candidate pool and constructs a matched
background separately for each profile-resolved target comparison.

10.2 Clean-control exclusions

A protein is excluded from control candidacy when:

  * any target rule accepted, proposed or ambiguously matched it;
  * it shares an independence block with a target;
  * it is an upstream input candidate and that exclusion is enabled; or
  * it fails one or more matching calipers.

This deliberately sacrifices sample size to reduce contamination.

10.3 Unit of matching

Matching occurs at the independence-block level. One deterministic
representative is selected per block. Preference order is:

  * eligible structure;
  * higher available confidence;
  * shorter sequence; and
  * lexical protein identifier as the final tie-break.

The same control block cannot be reused within one background selection.

10.4 Default E3 matching variables

The built-in E3 rules require:

  * at least one shared species label;
  * the same structure-eligibility state;
  * absolute log2 length difference <= 0.75; and
  * absolute domain-count difference <= 2.

Among candidates inside all calipers, the deterministic distance combines
length difference, domain-count difference, domain-architecture Jaccard
dissimilarity and scaled mean-confidence difference.

By default, the matcher requests three unused control blocks per target block
and requires at least three matched independent control blocks for a populated
background. If this cannot be achieved, the workflow fails rather than running
an underpowered unmatched comparison silently.

10.5 What matching does and does not solve

Matching reduces obvious differences in taxon, size, domain complexity and
structure availability. It does not guarantee exchangeability, eliminate all
phylogenetic dependence or create a causal estimate. Inspect the matching audit
and run sensitivity analyses with defensible alternative policies.


11. CIRCULARITY PROTECTION
--------------------------

If PF00646 helps label a protein as F-box, testing PF00646 as a newly discovered
confirmation of that same automated label would be circular. The package
therefore writes every label-defining domain to
label_definition_features.tsv and removes those accessions from the downstream
confirmatory domain and ML feature authority.

The exclusion scope is GLOBAL_CONFIRMATORY_DOMAIN_AND_ML within the campaign.
This strict scope prevents a domain used for one automated class from being
advertised as a novel signature of another class in the same run. The original
unfiltered domain input remains checksummed for audit.

The filtered output is domains.for_signature_analysis.tsv. Assessment coverage
is retained after feature removal so that removed hits do not turn into silent
missingness.

This safeguard removes direct feature reuse. It cannot remove every indirect
relationship between annotations, phylogeny, domains and structure. Results
remain provisional until independent review and validation.

13. STRUCTURAL ANALYSIS
-----------------------

13.1 Structure sources

The pipeline accepts an existing structures.tsv, a completed predecessor
structural-alignment resource, or a mapping of protein identifiers to AlphaFold
Database accessions. Existing models are reused when their coordinate and
sequence authorities validate. Requested AlphaFold acquisitions record every
success and failure rather than dropping missing models.

13.2 Confidence policy

The current completed-E3 adapter uses minimum mean pLDDT 50 for Foldseek
eligibility. This is a coarse full-model screen. Mean pLDDT does not guarantee
that every domain, interface or relative domain orientation is correct.
Residue-level confidence and PAE should be considered when interpreting a
specific motif or inter-domain arrangement.

13.3 Foldseek

Foldseek compares eligible coordinate models and provides pairwise structural
similarity evidence. The package invokes it through a safe argument list,
records the executable/version/cache identity and checks numeric bounds.
Pairwise edges must satisfy both the configured TM-score and coverage
thresholds before structural clusters are formed.

Default campaign thresholds are:

  structural TM score >= 0.50
  structural coverage >= 0.50
  Foldseek E-value <= 0.001
  Foldseek sensitivity 9.5

These are analysis settings, not universal definitions of fold identity.

13.4 Discovery and validation

Structural components are defined from discovery data. Held-out structures are
then projected onto those frozen components. This separation avoids deriving a
structural motif from all proteins and claiming the same proteins as an
independent validation.

13.5 Imported structural resource

The completed-E3 bridge verifies the Stage 09b manifest and its checksummed
datasets. Imported summaries remain distinct from structures generated inside
the new package. The provenance table records which authority supplied each
structural result.

13.6 Interpreting a structural signature

A target-enriched structural cluster means that the cluster is more prevalent
among assessed independent target blocks than assessed matched-background
blocks under the configured thresholds. It does not automatically identify a
minimal causal fold, active site, binding pocket or ligandable surface. Review
representative alignments, coverage, confidence, domain boundaries and
taxonomic breadth before assigning biological meaning.


14. SEQUENCE AND DOMAIN FEATURES
--------------------------------

The production-safe default discovers tripeptide presence features. A k-mer is
counted at protein level as present or absent, rather than allowing repeated
copies in one protein to dominate. Four-residue features can be enabled but
greatly increase the hypothesis space and compute requirement.

Domain features retain coordinates and explicit assessment states. Domain
sequences are extracted with the original coordinate mapping. Imported generic
features are accepted only through the fixed schema and retain their evidence
source and assessment authority.

Feature derivation provenance distinguishes discovery-defined features from
features derived using all data. An all-data-derived feature can be shown as
exploratory but cannot be promoted as held-out confirmation.


15. INDEPENDENCE BLOCKS AND DATA SPLITTING
------------------------------------------

Proteins are connected when they share a relevant OrthoFinder group, an exact
sequence, or a supplied near-redundancy cluster. Connected components become
indivisible independence blocks.

A stable hash of the block identifier and random seed assigns the entire block
to DISCOVERY or VALIDATION. The default validation fraction is 0.20. No member
of a block can appear in both partitions.

Association tests operate on blocks, not raw duplicated proteins. A block is
feature-positive when any relevant member has the feature. It is feature-
negative only when every relevant member was assessed and none was positive.
A partially assessed no-hit block is unknown and does not enter that feature's
denominator.

Blocks containing both target and background labels are excluded from the
corresponding comparison and counted explicitly. They are not forced into one
class.


16. ASSOCIATION STATISTICS
--------------------------

16.1 Contingency table

For one feature, partition and comparison, the package forms:

                       Feature present    Feature absent
  Target blocks                a                 b
  Background blocks            c                 d

Only assessed independent blocks enter a, b, c and d. Raw protein counts and
unknown block counts are also retained for transparency.

16.2 Prevalence and effect direction

Target prevalence is a / (a + b).
Background prevalence is c / (c + d).
Prevalence difference is target prevalence minus background prevalence.

A positive difference is TARGET_ENRICHED. A negative difference is
BACKGROUND_ENRICHED. Zero is NO_DIFFERENCE.

The sample odds ratio is (a*d)/(b*c) when defined. Infinite or undefined values
are represented explicitly rather than clipped into a misleading finite value.

16.3 Fisher exact test

The package implements a two-sided fixed-margin Fisher exact test using
hypergeometric table probabilities. The p-value sums all feasible tables whose
probability is no greater than the observed table probability, with a small
floating-point comparison tolerance.

The p-value measures compatibility with the null model. It is not the
probability that the biological hypothesis is false. A small p-value does not
measure effect size and a large p-value does not prove equivalence.

16.4 Wilson intervals

Target and background prevalence each receive a 95% Wilson score interval.
Wilson intervals behave better than the simple Wald interval near zero or one
and with modest denominators. The intervals quantify uncertainty in each
observed block prevalence; they are not confidence intervals for the
prevalence difference.

16.5 Local false-discovery correction

Within each comparison and partition, Benjamini-Hochberg correction is applied
separately by feature_type. This prevents a very large k-mer family from using
the entire multiplicity budget of a smaller prespecified domain or structural
family. The resulting field is q_value.

16.6 Study-wide false-discovery correction

A second Benjamini-Hochberg correction spans all configured comparisons within
each partition and feature_type. The resulting field is study_q_value.

At threshold 0.05, a q-value is interpreted as an FDR-controlled decision under
the assumptions of the procedure and the declared family of tests. It does not
mean that a particular row has a 5% probability of being false.

16.7 Discovery and validation

All eligible discovery features are tested. Only discovery features with local
q_value <= the configured threshold and non-zero prevalence difference become
frozen validation candidates. The validation partition is never consulted when
choosing those candidates.

Validation tests use the same feature identity and check direction as well as
local and study-wide q-values.

16.8 Evidence classes

DECISION_CANDIDATE__*
  Discovery passes study-wide FDR for a biological feature.

EXPLORATORY_LOCAL_ONLY__*
  Discovery passes local but not study-wide FDR.

EXPLORATORY_ALL_DATA_DERIVATION__*
  The feature definition used all campaign data and cannot be confirmatory.

QC_TECHNICAL_NON_BIOLOGICAL__*
  The feature describes technical availability or quality, not a biological
  signature.

Validation suffixes are:

  VALIDATED_STUDY_WIDE
  VALIDATED_WITHIN_COMPARISON
  DISCOVERY_ONLY
  DIRECTION_DISCORDANT
  NO_VALIDATION_DATA

NO_DISCOVERY_SIGNATURE means eligible tests completed but none passed local
FDR. NO_ELIGIBLE_FEATURES or INSUFFICIENT_SAMPLE_SIZE means the test was not
completed. These outcomes must not be conflated.


17. EXPLAINABLE MACHINE LEARNING AND SHAP
-----------------------------------------

17.1 Role of the model

The ML layer is complementary to association testing. It asks whether a
combination of features predicts the configured target/background label. It
does not replace the feature-wise Fisher tests and does not prove mechanism.

17.2 Feature selection

Technical feature types are excluded by default. Label-defining automated
domains are excluded earlier by the evidence bundle. Remaining non-constant
features are ranked without consulting class labels, using discovery document
frequency. A round-robin selection across feature types prevents abundant
k-mers from crowding out every domain or structural feature. The default cap is
500 features.

17.3 Fit and cross-validation

The model is elastic-net logistic regression. Default l1_ratio is 0.20 and
candidate regularisation strengths are 0.01, 0.1 and 1.0. Selection uses
StratifiedGroupKFold on discovery data. Every independence block stays within
one fold.

Protein rows receive inverse-block-size weights so a large duplicated block
does not dominate. Weights are then balanced between target and background
classes. Mixed-class blocks are excluded.

The final model is fitted only on discovery data. If the required samples,
independent groups, variable features or valid folds do not exist, the package
publishes a controlled non-fitted status instead of inventing a model.

17.4 Held-out metrics

When validation has adequate pure blocks in both classes, the package reports:

  ROC AUC
  average precision
  balanced accuracy at probability 0.5
  Matthews correlation coefficient
  Brier score
  held-out permutation importance

If validation is missing or underpowered, predictions and SHAP may still be
descriptive, but held-out performance claims are withheld and the model status
says why.

17.5 SHAP execution

SHAP runs for every fitted model. It is not optional in a valid campaign.
The implementation uses an interventional linear explainer with a discovery-
data background and reports additive contributions in log-odds space.

Outputs include:

  * a numeric ml_explanations table;
  * a global beeswarm plot;
  * a global bar plot;
  * deterministic per-protein waterfall plots;
  * PNG, SVG and PDF forms; and
  * an ml_plot_inventory table with exact scope and checksums.

17.6 SHAP interpretation

A positive SHAP contribution moves the fitted model toward the target class
relative to its expected log odds. A negative contribution moves it toward the
background. Magnitude describes contribution for this fitted model and this
sample. It does not measure biochemical importance.

Correlated features can divide or redistribute attribution. Read a correlated
feature set together, compare with prevalence and held-out permutation
importance, and return to the raw protein/domain/structure evidence. Never
describe a SHAP value as a causal effect.

20. SNAKEMAKE AND SLURM DESIGN
------------------------------

20.1 Generic normal-label DAG

workflow/Snakefile validates a campaign, runs the atomic analysis and verifies
the published result.

20.2 Generic evidence-led DAG

workflow/EvidenceSnakefile:

  1. creates and verifies the evidence label bundle;
  2. stops there by default;
  3. requires explicit provisional acceptance for campaign initialisation;
  4. invokes the normal analysis DAG; and
  5. independently verifies the final result.

This route works for any profile/rules pair, not only E3.

20.3 Completed-E3 DAG

workflow/E3Snakefile owns:

  1. preparation/verification of predecessor inputs;
  2. evidence proposal or review staging;
  3. mode-specific checksum-bound approval;
  4. campaign initialisation;
  5. atomic analysis; and
  6. final verification.

It supports human review, synthetic smoke testing and provisional evidence-led
execution.

20.4 Outer Slurm job

The shell launcher submits one bounded Slurm job with requested CPUs, memory
and time. Snakemake then runs the DAG inside that allocation using the local
profile. The launcher unsets inherited SLURM_CPUS_PER_TASK before sbatch and
exports PROTEIN_SIGNATURE_REQUESTED_CPUS to prevent an interactive allocation
from changing the requested CPU contract.

On this cluster, both account and partition must be barton.

20.5 Restart behaviour

Snakemake owns its state under WORK_DIR/workflow_state. Published bundles and
results are immutable. --resume is appropriate only when the exact config and
input checksums still agree. Do not delete markers to force incompatible data
through an old campaign. Use a new versioned work directory for changed inputs
or scientific rules.

29. KNOWN WARNINGS AND LIMITATIONS
---------------------------------

29.1 Provisional labels

Automated labels are hypotheses. Rules can inherit annotation errors,
taxonomic bias and incomplete Pfam coverage. The marker therefore keeps
scientific_interpretation_allowed FALSE.

29.2 Catch-all E3 classes

Six other_reviewed E3 targets have no automatic rule. They require a trusted
direct assignment. Empty output for these classes is expected in a purely
pattern-driven run.

29.3 Control availability

Strict matching can fail for rare taxa, unusual lengths, complex domain
architectures or classes whose structure coverage differs from the pool.
Failure is preferable to an undisclosed unmatched comparison. A policy change
requires a new ruleset version and sensitivity analysis.

29.4 Residual dependence

OrthoFinder and redundancy blocks reduce leakage but cannot guarantee that all
evolutionary dependence is captured. Closely related unlinked proteins may
remain.

29.5 Structural uncertainty

Mean pLDDT is a coarse filter. Flexible regions and domain orientations can be
wrong. Foldseek similarity depends on thresholds and coverage. Structural
association does not imply a binding pocket or biochemical activity.

29.6 Multiple testing

Local and study-wide FDR are both provided. Correlated hypotheses and adaptive
post-hoc interpretation still demand caution. Pre-specify comparisons and use
validation evidence.

29.7 SHAP

SHAP explains the fitted classifier. Correlated features can share attribution,
and a strong contribution is not a causal effect. Read SHAP only after model
status and held-out performance.

29.8 Original input availability

The portable result can be opened without original inputs. Computational resume
and evidence-bundle verification intentionally require the original recorded
authorities to remain byte-identical at their paths.

29.9 Mac flock warning

The Slurm controller requires the Linux flock utility. A test that invokes the
worker directly on macOS must supply a fixture implementation or be skipped as
Linux-specific. This does not affect execution on the Linux Slurm cluster.

29.10 Streamlit/SHAP import time

The comprehensive UI test can be slow because SHAP/Matplotlib and PDF rendering
initialise browser/plotting resources. Targeted UI validation has passed, but a
full local suite can take many minutes.

32. SCIENTIFIC SENSITIVITY ANALYSES RECOMMENDED AFTER THE FIRST RUN
-----------------------------------------------------------------

At minimum compare:

  * evidence rules with and without weak cluster-associated catalogue text;
  * direct curated seed anchors versus no direct anchors;
  * structure-required versus a clearly named sequence/domain-only analysis;
  * pLDDT eligibility thresholds such as 50 and 70;
  * alternative structural TM-score and coverage thresholds;
  * default three-controls-per-target matching versus another prespecified
    ratio where the pool permits;
  * strict species matching versus a defensible taxonomic-stratum match;
  * tripeptide features alone versus an explicitly budgeted addition of
    four-residue features;
  * HOG propagation enabled versus disabled; and
  * results at local and study-wide FDR thresholds without moving thresholds
    in response to desired genes.

Each sensitivity run needs a new campaign ID, work directory and versioned
configuration. Compare concordance of direction, effect size, held-out class
and representative structures, not only the number of q-values below 0.05.
